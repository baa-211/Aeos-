# DEC-001 — How Comments Reach the Record

## Question
Should the preview be able to write a drafted comment into a stage record, or must it stay clipboard-only?

## Why it is open
Comments drafted in the command interface are exported as Markdown for manual pasting. That keeps the preview strictly read-only, which the handoff requires, but it puts a copy-and-paste step between a thought and the record that is meant to hold it. Friction here means notes do not get written.

## Options
1. **Clipboard only (current).** Zero write surface. The preview cannot corrupt a record. Cost: every note needs manual pasting and committing.
2. **Local write endpoint with diff preview.** A small local server appends to the stage record and shows the diff for approval before it is applied. Cost: the preview gains a write path, and the handoff rule about not mutating files without explicit confirmation becomes a runtime guarantee rather than a structural one.
3. **Emit a patch file.** The preview writes a `.patch` to a scratch directory; the person applies it with `git apply`. Cost: still two steps, but no direct mutation of records.

## Blocks
Nothing today. It becomes urgent if comment volume grows enough that pasting is skipped.

## Resolution
**Accepted 2026-09-01: option 2, a local write endpoint with diff preview.**

The project owner rejected the clipboard flow directly: a step between writing a thought and the record holding it means the thought does not get recorded. Option 3, emitting a patch file, was also rejected as still two steps.

The read-only property is preserved by constraint rather than by absence. `preview/serve.py` binds to the loopback interface only, writes exclusively to Markdown records that already exist under `docs/`, cannot create or delete files, cannot follow symlinks, and appends under a named heading rather than rewriting a file. Git is never touched implicitly; staging and committing are separate calls a person makes, and the diff is returned first. The validator is never invoked from the server, so the interface can never appear to certify its own edits.

Opened as a file with no server running, the interface falls back to the clipboard and says which mode it is in.
