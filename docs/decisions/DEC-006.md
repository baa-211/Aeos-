# DEC-006 — A Conversation Inside the Command Interface

## Question
Should the command interface be able to send a question to a language model and show the reply, or must it stop at assembling a brief for the person to carry elsewhere?

## Why it is open
The prompt composer asked the person to type a question and then handed it back to them on the clipboard. The project owner asked the obvious question: why type it there at all?

The composer was built that way because `ROADMAP.md` defers *AI inside the deterministic validator*. On re-reading, that constraint is narrower than the way it was applied. The validator is the Go CLI. The preview is a separate track whose stated obligations are not to duplicate validation logic, not to become a second source of truth, to remain read-only by default, and never to make the core release less trustworthy. A conversation that drafts text a person then approves violates none of those.

The refusal was therefore over-cautious rather than principled, and it produced a control whose only function was to return text the person had just written.

## Options
1. **Keep the composer clipboard-only.** No network, no key, no third party. Cost: the interface asks a question it cannot carry, and the person context-switches to answer it.
2. **Send from the local server, holding the key server-side.** The browser talks only to `preview/serve.py`; the server holds the credential and talks to the provider. Cost: a network dependency in the preview, project content leaving the machine, and a credential to manage.
3. **Call the provider from the browser.** Simplest to build. Cost: the credential would have to reach the browser, which puts it in a page, in memory, and one mistake away from a log. Rejected outright.

## Blocks
Nothing. The composer works today; it is simply a worse experience than it should be.

## Resolution
**Accepted 2026-09-01: option 2, sent from the local server.**

Option 3 was rejected on the credential alone. A key that reaches the browser is a key in a page, and this project exists to find credentials in places they should not be.

The constraints that make option 2 acceptable, and which are conditions of it rather than commentary:

- **The validator is untouched.** The Go CLI gains nothing, calls nothing, and stays deterministic. `aeos check` produces identical output whether a key exists or not.
- **The key never leaves the machine's environment.** It is read from `ANTHROPIC_API_KEY` at request time, never written to the repository, never returned to the browser, never logged. `.env` is already ignored and `.env.example` documents the variable without holding one.
- **Replies are drafts, never records.** A model reply is untrusted content displayed in a session. It reaches a record only through the existing note path, which a person presses, and which writes under `## Memory` where its provenance is visible.
- **Nothing is inferred into AEOS truth.** The report, the findings, the record index and the declared stage all continue to come from `aeos check`. A reply never changes a status, resolves a decision, or alters a count.
- **Sending is explicit and stated.** Each send carries the stage's context off the machine to a third party. The interface says so before the first message rather than in documentation.
- **Absence degrades honestly.** With no key, or no server, the composer falls back to the clipboard and says which mode it is in. Nothing regresses for anyone who does not want this.
