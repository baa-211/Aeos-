# DEC-004 — Policy for Gitleaks False Positives in Documentation

## Question
When project documentation legitimately trips a scanner rule, is the response always to reword?

## Why it is open
Writing about cryptography reliably trips `generic-api-key`. This has happened twice, both in documentation about the scanner itself. Rewording worked, but it constrains what the project can write about its own security.

## Options
1. **Always reword (current).** No allowlist ever. Cost: some accurate technical prose cannot be written.
2. **Path-scoped allowlist for `docs/` only.** Source and configuration stay fully scanned. Cost: documentation becomes a place where a real secret could hide.
3. **Rule-scoped allowlist for `generic-api-key` in `docs/` only.** Narrowest option. Cost: still a hole, and the highest-recall rule is the one being narrowed.

## Blocks
Nothing yet. Each recurrence costs a rewrite.

## Resolution
Unresolved. Option 1 stands until the cost of rewording exceeds the cost of a scoped hole.
