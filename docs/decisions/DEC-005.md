# DEC-005 — Sequencing of the Account System

## Question
Should authentication be built before the product surface exists?

## Why it is open
A login screen was requested early. Accounts are a permanent commitment: password reset, recovery, migration and a credential store become obligations the moment they ship.

## Options
1. **Local vault.** Passphrase derives sealing material; state is encrypted at rest. No server, no reset flow, no breach surface. Email is a label, not a credential.
2. **OS keychain, no passphrase.** Zero friction, weakest if the machine is unlocked.
3. **Hosted accounts.** The only option enabling multi-device sync, and the only one that contradicts the v0.1 rule against a database or cloud dependency in the core.

## Blocks
Nothing. Deferred behind a proven CLI surface.

## Resolution
**Accepted 2026-08-31: option 1, deferred until the preview proves what state needs protecting.** A login screen gates nothing while AEOS is a CLI. The design is held: Argon2id-derived sealing material, XChaCha20-Poly1305, email as a label. Revisit when the preview holds state worth protecting.
