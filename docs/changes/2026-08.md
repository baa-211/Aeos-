## CHG-012 — Normalize Secret-Scanner Paths Across Scan Modes

Date: 2026-08-26
Status: Implemented

Normalized every Gitleaks-reported path to a project-relative, slash-separated form inside the secrets adapter before an AEOS finding is constructed.

Why: `gitleaks dir` reports absolute filesystem paths while `gitleaks git` reports repository-relative paths. Two defects followed. Deduplication keys on path, so a single secret present in both the working tree and Git history produced two findings and doubled the reported critical count. Separately, absolute paths reached the JSON report, so the same project produced different reports on different machines, contradicting the deterministic reporting contract accepted in M4.

Evidence: reproduced with real Gitleaks 8.30.0 against a repository containing two committed secrets that were also present in the working tree. Before: four critical findings. After: two. The JSON report is now byte-identical when the same project is checked from two different filesystem locations; previously it differed.

Security: no change to redaction, blocking behavior, or exit codes. A planted secret still yields `AEOS-SEC-001`, severity CRITICAL, and exit code 3. A secret outside the project root retains its absolute path rather than being misreported as project-local.

Tests: added cross-mode deduplication regression, a report assertion that no in-project finding carries an absolute path, a normalization table covering relative, nested, absolute, dot-segment and empty inputs, an outside-root case, and an idempotence check.

Result: `gofmt`, `go vet ./...`, `go test ./...` and build all pass. `internal/findings` coverage rose from 0.0% to 95.2%; `internal/secrets` from 74.7% to 77.6%.

## CHG-015 — Resolve Repository Identity: Migrate Module Path to `Aeos-`

Date: 2026-08-26
Status: Implemented

Migrated the Go module path from `github.com/baa-211/aeos-cli` to `github.com/baa-211/Aeos-` across `go.mod`, all Go imports, and documentation.

Why: the module path must match the repository URL for `go get` to resolve, because the path is the fetch address rather than a label. The user elected to keep the existing remote `https://github.com/baa-211/Aeos-.git` rather than rename it, so the module moved instead.

Options considered: rename the repository to `aeos-cli` (zero code change, GitHub provides redirects) or migrate the module path (codebase-wide edit). The user chose to keep the repository.

Accepted consequence: the path contains an uppercase letter. The Go module proxy and local module cache case-encode uppercase characters, so the module is addressed on disk and via the proxy as `github.com/baa-211/!aeos-`. This is valid and supported; it is cosmetically unusual and appears in cache paths and proxy URLs. The trailing hyphen is likewise valid.

Reversal cost: renaming the repository after publication would require a second module-path migration and would break any consumer already depending on the current path. This decision is cheapest to revisit before the first push and expensive afterward.

Verification: `go mod init` accepts both candidate paths (tested empirically on Go 1.24.4). After migration, `gofmt` is clean, `go vet ./...` passes, `go test ./...` passes across all seven packages, the binary builds with `-trimpath`, and `aeos check` self-validates with exit 0 against pinned Gitleaks 8.30.0.
